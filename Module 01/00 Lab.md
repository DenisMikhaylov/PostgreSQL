### 🧪 Лабораторная работа: Исследование физической структуры данных PostgreSQL/Postgres Pro

**Цель работы:** Изучить физическую организацию данных в СУБД PostgreSQL/Postgres Pro, освоить команды для просмотра табличных пространств, баз данных, файловой структуры отношений, страниц и кортежей, а также научиться создавать собственное табличное пространство.

#### 1. Подготовка и проверка окружения

##### 1.1. Проверка установки и версии Postgres Pro

Сначала убедимся, что Postgres Pro установлен в системе, и узнаем его версию. Откройте терминал и выполните следующие команды.

**Команда 1: Проверка версии сервера**
```bash
# Попробуйте найти исполняемый файл Postgres Pro и запросить его версию
pg_config --version
```
Если эта команда не сработает, попробуйте поискать другие возможные имена, например `postgres --version` или `psql --version`. Результат покажет, какая именно версия установлена (например, `PostgreSQL 15.1` или `Postgres Pro 15`).

**Команда 2: Проверка через менеджер пакетов**
```bash
# Для систем на основе Debian/Ubuntu
apt list --installed | grep postgrespro
```
Эта команда покажет список установленных пакетов, в имени которых есть "postgrespro".

##### 1.2. Подключение к базе данных

По умолчанию в системах PostgreSQL/Postgres Pro создается служебная учетная запись `postgres`. Подключитесь к серверу с ее помощью.

```bash
# Переключитесь на пользователя postgres
sudo -u postgres psql
```
После успешного подключения вы увидите приглашение psql, например: `postgres=#`.

#### 2. Исследование табличных пространств (Tablespaces)

Табличные пространства определяют физическое расположение данных в файловой системе.

##### 2.1. Просмотр существующих табличных пространств

В psql выполните следующие команды:

```sql
-- 1. Просмотр списка табличных пространств (краткий формат)
\db

-- 2. Просмотр списка с дополнительной информацией (например, размер)
\db+
```
Вы увидите как минимум два стандартных табличных пространства: `pg_default` (для пользовательских данных) и `pg_global` (для общих системных каталогов).

```sql
-- 3. Запрос к системному каталогу pg_tablespace
SELECT spcname, pg_tablespace_location(oid) FROM pg_tablespace;
```
Этот запрос покажет имена табличных пространств и их физические пути в файловой системе.

#### 3. Исследование баз данных (Databases)

##### 3.1. Просмотр списка баз данных

```sql
-- 1. Просмотр списка баз данных
\l

-- 2. Просмотр с дополнительной информацией
\l+
```
Обратите внимание на колонку "Tablespace" — она показывает, какое табличное пространство используется по умолчанию для каждой базы данных.

```sql
-- 3. Запрос к системному каталогу pg_database
SELECT datname, datdba, datistemplate, datallowconn, datacl FROM pg_database;
```

#### 4. Исследование физической структуры: слои, сегменты, страницы и кортежи

##### 4.1. Создание тестовой таблицы

Для исследования создадим небольшую тестовую таблицу и наполним ее данными.

```sql
-- Создание таблицы
CREATE TABLE test_storage (
    id SERIAL PRIMARY KEY,
    data TEXT
);

-- Вставка нескольких строк
INSERT INTO test_storage (data) VALUES 
    ('Первая строка'),
    ('Вторая строка, немного длиннее'),
    ('Третья строка, которая может быть еще длиннее для демонстрации');
```

##### 4.2. Поиск физического файла таблицы (Сегменты)

Каждая таблица и индекс хранятся в одном или нескольких файлах (сегментах) в каталоге данных.

```sql
-- 1. Получение OID (Object Identifier) таблицы
SELECT oid, relname, relfilenode FROM pg_class WHERE relname = 'test_storage';

-- 2. Получение пути к основному файлу (сегменту) таблицы
SELECT pg_relation_filepath('test_storage');
```
Функция `pg_relation_filepath` вернет путь относительно каталога данных (PGDATA), например: `base/16384/16385`. Здесь:
*   `base` — подкаталог для табличного пространства `pg_default`.
*   `16384` — OID базы данных.
*   `16385` — номер файлового узла (filenode) таблицы. Это и есть имя первого сегмента.

##### 4.3. Просмотр структуры страницы и кортежей

PostgreSQL хранит данные на 8-КБ страницах. Кортежи — это физические строки на этих страницах.

```sql
-- 1. Просмотр скрытого системного столбца ctid (страница, кортеж)
-- ctid показывает физическое местоположение каждой строки: (номер_страницы, номер_кортежа)
SELECT ctid, id, data FROM test_storage;
```
Вы увидите что-то вроде `(0,1)`, `(0,2)`, что означает, что строки находятся на странице 0 и являются 1-м и 2-м кортежами на ней.

```sql
-- 2. Получение информации о количестве страниц в таблице
SELECT relpages, reltuples FROM pg_class WHERE relname = 'test_storage';
```
Здесь `relpages` — это количество страниц, занимаемых таблицей, а `reltuples` — примерное количество строк (кортежей).

##### 4.4. Просмотр служебных слоев (FSM и VM)

Для каждой таблицы существуют дополнительные файлы-слои: карта свободного пространства (FSM) и карта видимости (VM).

Их имена образуются путем добавления суффиксов `_fsm` и `_vm` к имени основного файла (filenode). Вы можете убедиться в их существовании, выйдя из psql и заглянув в файловую систему. Сначала узнайте путь к вашим данным.

**В psql:**
```sql
-- Показывает путь к каталогу данных (PGDATA)
SHOW data_directory;
```
**Выйдите из psql:**
```sql
\q
```

**В терминале:**
Перейдите в каталог, который вы узнали из команды `SHOW data_directory;`, а затем в подкаталог, который показала функция `pg_relation_filepath`. Например:
```bash
# Пример: переход в каталог с данными базы данных
cd /var/lib/postgresql/15/main/base/16384/

# Просмотр файлов, относящихся к нашей таблице (подставьте свой filenode)
ls -la | grep 16385
```
Вы должны увидеть файлы:
*   `16385` — основной файл (сегмент 0).
*   `16385_fsm` — карта свободного пространства.
*   `16385_vm` — карта видимости.

#### 5. Создание собственного табличного пространства

Теперь создадим новое табличное пространство вручную. Для этого нужно, чтобы в системе существовал каталог, в котором будут храниться данные.

##### 5.1. Создание каталога

**Выйдите из psql**, если вы все еще в нем, и выполните в терминале:

```bash
# Создаем каталог для нового табличного пространства
sudo mkdir -p /usr/local/pgsql/tablespaces/my_tablespace

# Назначаем владельцем пользователя postgres
sudo chown postgres:postgres /usr/local/pgsql/tablespaces/my_tablespace
```

##### 5.2. Создание табличного пространства в psql

Снова подключитесь к psql:

```bash
sudo -u postgres psql
```

И выполните команду:

```sql
CREATE TABLESPACE my_tablespace LOCATION '/usr/local/pgsql/tablespaces/my_tablespace';
```


##### 5.3. Проверка создания

```sql
-- Проверяем, что новое пространство появилось в списке
\db+
```
Вы должны увидеть `my_tablespace` в списке.

##### 5.4. Использование нового табличного пространства

Теперь вы можете создавать объекты в новом табличном пространстве.

```sql
-- Создать базу данных в новом табличном пространстве
CREATE DATABASE test_db_with_new_ts TABLESPACE my_tablespace;

-- Или создать таблицу в новом табличном пространстве (находясь в любой БД)
CREATE TABLE test_in_new_ts (id int) TABLESPACE my_tablespace;

-- Проверить, где лежит файл новой таблицы
SELECT pg_relation_filepath('test_in_new_ts');
```
Путь должен указывать на ваш новый каталог `/usr/local/pgsql/tablespaces/my_tablespace/`.
